## Question
Do buffers from `swofty::game_mem::alloc` (game allocator vtable +0x18, through the core) work as the storage of the game's R&D card vector and the upgrade-type metadata vector, and does `game_mem::free` (+0x38) release the old buffer and temporary NeStr storage without heap errors?

## Hypothesis
`g_Ne_DefaultAllocator` and the builder's allocator (+0x298) are Ne allocator objects whose +0x18 is alloc(self, size, align) and +0x38 free(self, p) (`g_Ne_DefaultAllocator` record notes; core hub tabs and live bus already call +0x18). The core calls the same slots after checking the object, so the add-on's behaviour does not change: 8 cards in the box grid, the metadata rescue still fills the holder.

## Promotes

- `g_Ne_DefaultAllocator` vtable slots +0x18 alloc, +0x38 free (globals notes)
