# T271 Does ICE wear 1.0 turn into an engine blown or seized flag, and does the car retire?

- Requested by: engine-re, 2026-11-18
- Status: draft
- Session: (filled by the lead when batched)

## Question
When an add-on sets the player's Engine wear_ice (+0x254c) to 1.0 once in a Grand Prix race, does Car_Engine_UpdateWear set Engine state_flags +0x2530 bit 0 or bit 1 on its next step, does UDP CarDamage report engineBlown / engineSeized, and does the terminal-damage system retire the car?

## Hypothesis
Car_Engine_UpdateWear: at ICE >= 1.0 with CarLive+0x130 bits 6 and 1 and +0x131 bit 0 set it rolls the CarLive+0x178 LCG, 50/50 seized (bit 1, needs +0x131 bit 5) or blown (bit 0, needs bit 4), then pins ICE at 0.99. 0x142d00060 copies bit 0 to UDP engineBlown and bit 1 to engineSeized. Car_TerminalDamage_EvalPartLevels then maps the engine part to level 1.0 (terminal only when its table and system+0xf90 allow it).

## Promotes
- `Car_Engine_UpdateWear` (failure roll), `CarEngine.state_flags` bits 0/1, `Car_TerminalDamage_EvalPartLevels`, note on `Game_TelemetryUdp_CollectDrsZones`

## User steps
1. Offline Grand Prix race, damage Standard, UDP telemetry on.
2. On the straight press the test key once. Keep driving 10 s.
3. Repeat in a second race (to see the other 50/50 outcome).

## Expected log lines
- `st=0x01|0x02 ice=0.99` within one step after the write -> proves the roll and the pin.
- UDP engineBlown or engineSeized = 1 -> proves the bit names.
Pass rule: both. Fail rule: no flag after 2 s with all gate bits set.
