# T310 Size ladder for big track ERPs: which heap fills first?

- Requested by: engine-re, 2026-11-20 (for the editor chat "EXE und ERP files in Track-Editor")
- Status: draft
- Session: (filled by the lead when batched)

## Question
When a single merged track ERP grows (resources, MB, VPTimes), which engine heap reaches its capacity first, and how much room is left at the grid?

## Hypothesis
Static (core.md#track-erp-size-limits): no fixed resource or instance count (resource map grows: `Ne_RobinHoodMap_Rehash`, `Ne_RobinHoodMap_GrowForInsert`). Candidates by capacity: GAME_DEFAULT (1024 MiB with Swofty heap_sizes; VPTimes copies), EGO_ERP_TEMP (500 MiB, transient per resource), EGO_APPLICATION (70 MiB, resource proxies), EGO_UPDATE_TASK (370 MiB; EGO_WORLD/EGO_PHYSICS), EGO_GFX_MODEL_RESOURCES (320 MiB), EGO_GFX_RESOURCES (300 MiB), EGO_GFX_SHARED (804 MiB), TRACK_INFO (52 MiB). Expected first to fill on the old 334 MB case: GAME_DEFAULT on stock 390 MiB; with 1024 MiB a renderer heap or VRAM.

## Promotes
- core.md#track-erp-size-limits table (capacities) to confirmed; `Ne_MemoryMap_CreateHeap` expand rule for every listed heap.

## Build
- exe: F1_25.exe 1.0.145 (runtime) with the KB build mapping; swofty_core with heap_sizes active (`[heap] GAME_DEFAULT heap armed` line).
- data: (a) stock Bahrain, (b) AVUS 621.9 MB, (c) packages of about 20k and 25k resources, (d) merged ERPs of about 280 MB and 320 MB, (e) VPTimes 334 MB (the old Hockenheim R23 class).

## Trace config
1. At the grid (first green frame) and once after the race start: for each heap name above, registry 0x14612a410 vt+8(name), then heap vt+0x60 capacity, vt+0x68 used, vt+0x70 free, vt+0x80 largest free (the fields `Ne_ReportMemoryError` prints). Also the redirects VIRTUAL_PERFORMANCE, EGO_WORLD, EGO_PHYSICS, TRACK_INFO_HEIGHT.
2. DXGI QueryVideoMemoryInfo (local: Budget, CurrentUsage) at the same moments.
3. Process private bytes and system commit (as in S6).
4. Keep the Ne_ReportMemoryError hook armed (pool name + numbers on any failure).

## User steps
1. Grand Prix, each package (a) to (e), load to the grid, start the race, 1 lap, quit to menu. One package per game start.

## Expected log lines
- `heap <name> capacity <n> used <n> free <n> largest <n>` per heap and package -> proves which heap grows with which package property.
- On a failure: `Ne_ReportMemoryError ... Pool <name>` -> names the limiting heap.
Pass rule: every package logs all heaps; the heap with the smallest free/largest at (c)-(e) is the limit to raise (Swofty heap_sizes Spec row). Fail rule: crash without a heap line -> the limit is not a heap (VRAM or a count), next test on the GPU side.
