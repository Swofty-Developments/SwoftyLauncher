# T014 Does the ERS mode guard keep an F1 2012 Season Grand Prix running past the session start that crashed at Car_Powertrain_Step+0x5df?

- Requested by: ers-uninit, 2026-10-30
- Status: draft
- Session: (filled by the lead when batched)

## Question
With the ERS mode guard in core, does a Grand Prix on the F1 2012 Season box `bdx_s5_2012` get past the first physics steps of the session (the crash `ACCESS_VIOLATION at F1_25.exe+0x46e286f`, `Car_Powertrain_Step+0x5df`, about 0.1 s after `StateSession` is entered; EA build `F1_25.exe+0x46d8aff`) and run a race to the flag? Which car's ERS mode was out of range, and on which load?

## Hypothesis
The HRT (`bdx5a11`, konnersport/konnerspor2) and Marussia (`bdx5a12`, zenith/zenit2) handling files of F1 2012 Season 1.1.1 have no top-level `EnergyRecoverySystem` section, while the other ten teams and the stock story cars have one. Such a car gets no ERS system at create. `Car_Systems_Reset_Body` re-runs `Car_Assets_CreateSystemForPerformanceMode`, which creates a system the car lacks (for example from the equal-performance base VTF) and runs its Read, Init and a Reset without 0x200 when its arg is 1, so `Car_Ers_Reset_Thunk` never sets `ers_mode` (+0x1a68) and the step indexes the mode table with whatever the allocator left there (V2124, V2125). The guard at `site_Car_ErsGearModifierLoad` (signature `car.ers_gear_modifier_load`) runs the system's own Reset with 0x10|0x200 when the mode is outside 0..3. Which reset creates the system, and whether the equal-performance setting matters, is not traced.

## Promotes
- `site_Car_ErsGearModifierLoad`: L2 -> L3 on the build the run used, with the `[ers] car` line as the trace.
- `Car_Create_EnergyRecoverySystemSystem` (unset mode, V2124) and `Car_Systems_Reset_Body` (V2125): L2/L3 notes confirmed when the `[ers] car` line names a 2012 HRT or Marussia car.
- A crash in `Car_Powertrain_Step` or `Ai_Update_VehicleDriver` with the guard armed demotes the "a reset is enough" claim and keeps the issue open.

## User steps
1. Launch through the launcher with the profile above. At the home screen, check `loader.log` for the guard lines (below).
2. Grand Prix: pick the F1 2012 Season box (`bdx_s5_2012`), any 2012 driver, Abu Dhabi (or Interlagos), dry, weekend type short (one practice or straight to qualifying and race), race length 3 laps (5%). Car performance: Equal if the option is offered.
3. Start qualifying, drive one lap, then go to the race and drive it to the flag. Where the menu allows, restart the session twice and drive a lap after each restart.
4. Back to the main menu and repeat step 2 and 3 with car performance Realistic and Mexico, Very Wet.
5. Quit from the main menu and keep `loader.log` and any crash report.

## Expected log lines
- `core mixin set 'swofty_core\.dll \(ers mode guard\)': 1 mixin` → the guard was offered.
- `\[core\] site site_Car_ErsGearModifierLoad at 0x[0-9a-f]+ \(base\+0x46e286f\) installed` (Steam) or `base\+0x46d8aff` (EA) → the site resolved and the hook is in.
- `\[ers\] mode guard armed` → the set installed.
- `\[ers\] car [0-9]+: ERS mode -?[0-9]+ out of range; set to 1 \(Medium\)` as a session starts → the guard met a car whose ERS mode was never set (the load that would have crashed). The mode varies per load; a load where the leftover value happens to lie in 0..3 logs nothing and did not crash before either.
Pass rule: steps 2 to 4 finish without a crash and the first three lines are logged. Fail rule: any crash with `F1_25.exe+0x46e2` (Steam) or `+0x46d8` (EA) in its stack, a crash in `Ai_Update_VehicleDriver` at a 2012 race start, or the guard lines missing.
