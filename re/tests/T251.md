# T251 Do the DRS and Overtake buttons still set the CarLive input bits on a car without DRS/ERS?

- Requested by: engine-re, 2026-11-18
- Status: draft
- Session: (filled by the lead when batched)

## Question
On an era car without DRS and without ERS modes, do the in-game DRS and Overtake buttons still set InputRecord flags bit0 / bits 21-22 (written by `Sess_HumanController_Update` 0x1438959c0), CarLive+0x1b8 bit2 / +0x1b9 bits 3-4 (written by `Sess_ControllerSystem_ApplyRecord` 0x14389a2b0) and the latched copies CarLive+0x1ec bit2 / +0x1ed bits 3-4 (`Car_Physics_AdvanceCar` 0x14473fd80)?

## Hypothesis
Static: the human controller reads the actions without any car check and ApplyRecord copies the bits for the human mode. Only the consumers (Game_DRS_UpdateCars, Game_ErsSystem_Update) check availability. So an add-on can read the DRS / Overtake press from CarLive (or the InputRecord) on every car and use it as an era button.

## Promotes
- `Sess_HumanController_Update` flag notes, `Sess_ControllerSystem_ApplyRecord` flag routing, `InputRecord.flags` (L2 -> L3)

## Build
- exe: F1_25.exe sha256 d873a1c8d2044cef... (KB build)
- loader / plugins: current Swofty core + swofty_trace.dll (lead fills md5)
- data files: an era season package with a no-ERS / no-DRS car
- install: only `version.dll` and `swofty/`

## Trace config
Trace-only, on changes only: after `Sess_HumanController_Update` returns (vtable slot, signature session.human_controller) log dword [[rcx+8]+0x1c]; for the player car log bytes CarLive+0x1b8, +0x1b9, +0x1ec, +0x1ed once per second.

## User steps
1. GP or time trial with the era car, DRS and Overtake bound to wheel buttons (default bindings are fine).
2. On a straight press DRS 3 times, then hold Overtake 2 s, then press it 3 times.

## Expected log lines
- `flags=` with bit0 while DRS is held; bit21 while Overtake is held and bit22 on the press.
- `1b8=` bit2 with DRS; `1b9=` bits 3/4 with Overtake; `1ec` / `1ed` the same one tick later.
Pass rule: the bits follow the buttons on the era car. Fail rule: the bits stay 0.
