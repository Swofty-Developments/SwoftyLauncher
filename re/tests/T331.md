# T331 What does the game do today with a fuel-mix request of 4?

- Requested by: engine-re, 2026-11-20
- Status: draft
- Session: (filled by the lead when batched)

## Question
If the player's controller fuel request (InputRecord +0x00) is set to 4 by a test hook, does the game keep the car in its current mode and does the MFD show the nearest offered row, with no crash in single player?

## Hypothesis
`Sess_ControllerSystem_ApplyRecord` drops a request above 3 (cmp edx,3 / jg 0x14389bacf), so the FuelECU keeps its mode. `Game_Mfd_FuelMix_Update` selects the nearest lower offered row when bit 4 is not offered (0x1417889d4..0x141788a19). No other reader of the request was found. This is the safety base of the virtual route (the request must never be 4 online: the controls message is ranged 0..3, 0x1432491ce).

## Promotes
- `Sess_ControllerSystem_ApplyRecord` (request bound), `Game_Mfd_FuelMix_Update` (fallback row).

## Build
- swofty_core test build with a trace-only reader plus one test write of InputRecord+0x00 = 4 for the player (offline only).

## Trace config
1. Log InputRecord+0x00, CarFuelEcu+0x128 and sub+0x328 every frame for 5 s after the write.

## User steps
1. Grand Prix practice, stock track. 2. Trigger the test write once. 3. Drive 30 s, open the fuel MFD.

## Expected log lines
- request 4, fuel_mode unchanged -> the drop is proven.
Pass rule: fuel_mode unchanged, MFD shows a valid row, no crash. Fail rule: fuel_mode becomes 4 or the game crashes.
