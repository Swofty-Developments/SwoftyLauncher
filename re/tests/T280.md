# T280 Does a live write of the player's ctrlSys TC float change traction control at once, and how long does it hold?

- Requested by: engine-re, 2026-11-18
- Status: draft
- Session: (filled by the lead when batched)

## Question
With the TC assist set to Off in the menu, write 0.3, then 1.0, then 0.0 into the player's controller-system record float `[g_Live_ControllerSystem 0x146096578]+0xcc+veh*0x14` (veh = player car byte CarLive+0xe8) during a lap: do the input float (+0x19c of `[[car+0xe0]+0x58]`), BrakeECU +0x21e0 and solver +0x504 follow on the next physics tick, and is the value overwritten (by `Game_Player_ApplyAssistsToVehicle`) after a pit stop, a pause-menu assist change or a controller handover?

## Hypothesis
Static (engine-re era-tc round): `Sess_ControllerSystem_ApplyRecord` 0x14389a2b0 copies clamp01(record +0xcc) to input +0x19c every frame for a HUMAN-mode car (read 0x14389a3d8, store 0x14389a3fd); `Car_Physics_AdvanceCar` copies clamp01(+0x19c) to BrakeECU +0x21e0 (store 0x1447404f1); `Car_Solver_PrepareDrivetrain` sets solver +0x504 = max(BrakeATCStrength, +0x21e0) (0x1446db74c / 0x1446db793). Only `Game_Player_ApplyAssistsToVehicle` writes the record (0x1424243e2 / 0x142424403 / 0x14242444b), and it runs on MessageRefreshDifficultyData, MessageGameModeChanged and message_controller_type_changed (pit-lane AI handover included). So the write acts within one frame and holds until one of those messages.
