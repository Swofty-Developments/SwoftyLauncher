# T301 Does a !pkg whose chunks start between 8 and 16 MiB load when the five 23-bit masks are widened to 24 bits?

- Requested by: engine-re, 2026-11-19
- Status: draft
- Session: (filled by the lead when batched)

## Question
With the immediates of the five `and r, 0x7fffff` sites patched to 0x00ffffff, does a `.ui` / `.idf` package with chunks and value tables between 8 and 16 MiB open and draw, and does any other reader of chunk refs still read 23 bits?

## Hypothesis
Static reading (ui_system.md#tree-limits): the loader masks chunk and table refs with 0x7fffff at `Vm_Open_Pkg` 0x143927752, `Vm_Pkg_ResolveValueTables` 0x14392731a / 0x14392735a and `Vm_Pkg_ResolveObjectChunk` 0x14392f883 / 0x14392fc60 (Steam 1.0.145: 0x143929ce2, 0x1439298aa, 0x1439298ea, 0x143931e13, 0x1439321f0), then stores positive deltas, so later readers never see the file offset. Chunk refs carry tag 0x80 in bits 24..31, so bit 23 is free for the offset. Expected: the package loads; the cap moves from 8 to 16 MiB (not unlimited).

## Promotes
- `Vm_Open_Pkg`, `Vm_Pkg_ResolveValueTables`, `Vm_Pkg_ResolveObjectChunk` (L3 on pass)

## Trace config
