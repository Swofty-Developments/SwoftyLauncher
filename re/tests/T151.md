One question only. If it splits into two, file two tests.

## Hypothesis
Game_GarageCrewModule_SpawnGarageCrew (0x140388cf0) builds a vector of {assignment record, slot} for one garage and stores crew instance number r14d at [rsp+r14d*8+0x290] with no bound (0x14038944c); a third record in a garage overwrites the vector pointer at [rsp+0x2a0], which the epilogue frees through GAME_DEFAULT (0x14038c7f4). Six 1.6.11 reports (Melbourne practice 1, `Game_Garage_OnSessionLoaded` > `SpawnGarageCrew`, heap error `Invalid address ... GAME_DEFAULT`) fit it. Core's garage crew guard lowers the vector end at site_Game_GarageCrew_SpawnVector (signature `game.garage_crew_spawn_vector`) to the first two records whose slot is below 2, so the load finishes and the third car races without a garage crew.
