# T151 Does the standings track guard keep Team HQ > Standings open in a Driver Career whose calendar has a round at a community track that is now turned off?

- Requested by: career-re, 2026-10-31
- Status: draft
- Session: (filled by the lead when batched)

## Question
With the standings track guard in core, does Team HQ > Standings open in a Driver Career whose calendar has a round at a community track that has since been turned off in the launcher (the crash `ACCESS_VIOLATION reading 0x2c0 at F1_25.exe+0x181e1a1`, `Career_Standings_BuildWeekendNode+0xaa1`; EA build `F1_25.exe+0x18186f1`), and which round does the guard skip?

## Hypothesis
`Career_Standings_BuildWeekendNode` looks each round's track (Weekend +0x278) up in the career's TrackDataSystem (CareerEntity +0xf58) and reads the record's +0x2c0 without a null check on the path where the standings view's byte +0x4a is set. A track that is off has no TrackDataRecord, so that round's lookup gives 0 (V2194). The guard at `site_Career_StandingsWeekendTrackLoad` (signature `career.standings_weekend_track_load`) sends a null record to `site_Career_StandingsWeekendTrackDone` (signature `career.standings_weekend_track_done`, V2195), the game's own no-record path, so that round shows no track and the other rounds are unchanged.

## Promotes
- `site_Career_StandingsWeekendTrackLoad` and `site_Career_StandingsWeekendTrackDone`: L2 -> L3 on the build the run used, with the `[career] standings: round` line as the trace.
- `Career_Standings_BuildWeekendNode`: L1 -> L2 when the line names the round whose track was turned off.
- A crash in `Career_Standings_BuildWeekendNode` with the guard armed demotes the "the no-record path is enough" claim and keeps the issue open.

## Build
- exe: F1_25.exe sha256 d873a1c8d2044cef2fd76c99c9d5a97649c5b815d055540995105f46619865ae (Steam). Repeat on the EA App build (pe_timestamp 1789128892, the site at 0x1418186f1) when that copy is available.
- loader and core: `native/dist/` of branch `fix/standings-missing-track-guard` (or a release that carries it); record the `swofty_core.dll` md5 from the build log.
- addons: one community track addon (any track that adds a new round to the Driver Career calendar). Nothing else.
- install: the launcher places `version.dll` and `swofty/`; nothing else.

## Trace config
None. The `[career]` and `[core]` lines in `loader.log` are the evidence.

## User steps
1. In the launcher, turn the community track addon on. Play, start a new Driver Career and add that track to the calendar as a round (any round after round 1). Drive or skip to the end of round 1 so the standings have one result, save and quit to the desktop.
2. In the launcher, turn that track addon off. Play, load the same Driver Career.
3. Open Team HQ > Standings. Switch between the drivers' and teams' standings and the season results tab, then close the screen and open it again.
4. Quit from the main menu and keep `loader.log` and any crash report.

## Expected log lines
- `core mixin set 'swofty_core\.dll \(standings track guard\)': 1 mixin` → the guard was offered.
- `\[core\] site site_Career_StandingsWeekendTrackLoad at 0x[0-9a-f]+ \(base\+0x181e1a1\) installed` (Steam) or `base\+0x18186f1` (EA) → the site resolved and the hook is in.
- `\[career\] standings guard armed` → the set installed.
- `\[career\] standings: round [0-9]+ has no track data \(track [0-9]+ is off\); skipped` when the standings open → the guard met the round whose track is off (the read that would have crashed), once per round.
Pass rule: step 3 finishes without a crash, the round at the turned-off track shows no track name or flag, the other rounds look as before, and the four lines are logged. Fail rule: any crash with `F1_25.exe+0x181e` (Steam) or `+0x1818` (EA) in its stack, or the guard lines missing.
