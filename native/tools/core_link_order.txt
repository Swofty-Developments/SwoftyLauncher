# The order swofty_core.dll links its objects in. The C++ runtime runs their static initializers in the reverse of
# it (lld lays out .ctors in link order and the mingw runtime calls the list from its end), and the destructors they
# register at exit in it. It is the order of the single zig command the core was built with up to 1.9: the
# separately compiled objects first, then the core sources in the order that command listed them. build_graph.py
# links a source missing from this list after the listed ones, sorted by path, and stops when a listed file is gone.
# tools/core_init_order.txt holds what this order decides (the units with static constructors, the inline variables
# they initialize, the units with destructors, the SDK mixin list, the on-load sequence and the binding uses), and
# the build fails when it changes or a unit with static objects is not listed here.
