# 1.9.81

Swofty Launcher for F1 25 1.9.81 records the exit code of a game the EA app starts, logs launcher updates and the career hub's calendar, keeps an add-on at the version it had when its update stops halfway, and stops **Play** before a damaged add-on loads.

## Add-ons

- An add-on install or update that stops halfway, such as when the launcher closes, leaves the add-on at the version it had. The next start deletes the unfinished copy and writes the job's result to `state/registry.log`. See [Downloads](/using/addon-browser#downloads).
- **Play** stops with a **Reinstall** button when a file that the build or the game loads from an add-on that is on is missing, empty, all zeros, or no longer what its install wrote.
- `swofty addons verify [<id>]` reads every file of the installed add-ons, or of one, against the sizes and CRC-32s its install wrote, lists the damaged files and exits with status 1 if any would stop **Play**. See [`swofty addons`](/reference/cli#swofty-addons).

## Logs

- On Windows, a session started through the EA app reads the exit code of F1 25 when it closes. The session log says `[ea app] F1 25 exited (pid <pid>, exit code 0x<code>)`, with the crash's name for a crash code, and `end.json` holds the code that Send Logs and the crash diagnosis read. This includes the vanilla profile, whose sessions had no exit code before. See [EA app](/reference/launch#ea-app).
- `launcher-app.log` says whether the running launcher can update itself, with its path and the reason when it can't, and records each failed update check, each update installed or failed with its error, and the restart after it. See [Send Logs](/using/send-logs).
- In Driver Career, `loader.log` lists the calendar items running on the current day each time the career hub opens, with the item the game's calendar check picks, and lists them again under `[career] hub left at once` when the hub closes within a second of opening.

## Launcher

- The launcher shows an add-on list status only for the differences a start keeps.
