# 1.9.86

Swofty Launcher for F1 25 1.9.86 records Time Trial laps on the EA app copy of F1 25 1.0.145 and names both HUD add-ons when two claim the same part of the HUD.

## Fixes

- Time Trial laps on the EA app's F1 25 1.0.145 are recorded, and the in-game boards run there. Since that game update no lap was written on an EA app copy: `loader.log` said `[boards] off`, `[direct] Time Trial setup off`, `[shaders] live car signals are unavailable` and `[laps] NO LAP IS RECORDED IN THIS SESSION`. See [The Time Trial plugin](/std/systems/laps#the-time-trial-plugin).
- On the EA app's 1.0.145, shader rules read the `car.*` signals other than `car.surface` and `car.wetness`, and `session.lap` for the player's car. See [Signals](/reference/addons/shaders#signals).
- The core's direct start and title helper, which `swofty test` uses to start F1 25 in a test's state, run on the EA app's 1.0.145. See [Testing your addon](/std/testing).

## Add-ons

- When two HUD add-ons claim the same part of the HUD, Play is refused with both add-ons named, the part they share and which to turn off. Project Halo and TV Timing Tower both replace the Track Position list; with both on, Play says `the HUD elements do not compose: Project Halo and TV Timing Tower both replace the Track Position list, and only one of them can switch the game's own list off; turn Project Halo or TV Timing Tower off in this profile`. Until now it said `the preview element id of mask is already used` and named no add-on. See [When another addon claims the same part](/reference/ops/hud#when-another-addon-claims-the-same-part).
- The same refusal names both add-ons when two show and hide one lap counter or flag part, and when two set the HUD editor preview of one element differently.
- A part of the HUD editor preview that another add-on's copy already hides or fills the same way is kept once. Until now any part the copy already listed refused Play.
