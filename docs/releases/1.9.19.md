# 1.9.19

## Changes

- `loader.log` has two more `[perf]` lines every minute. The first lists the `VirtualQuery` calls that swofty code makes, with their time, module and top call sites, and how many pages the core's memory checks looked up. The second has the process's CPU use beside the CPU use of the threads that swofty code started. The busiest probes in the minute line now show calls per second.
- `loader.log` names each of the game's own messages (popups) once per session, for example `[popup] game message 'f1w_car_offline'`.
- Settings > General has a **Home screen video** switch. Turned off, the F1 25 home screen has no latest-video card.

## Fixes

- Continuing a saved Grand Prix no longer asks you to go online when the season doesn't use the F1 World car. The game compared the save with an F1 World car entry that, on some profiles, points at the normal F1 cars; the check now only applies to saves that really use the F1 World car.
- Shaders no longer flicker on and off with the game's XeSS frame generation (used on Intel Arc and set up by the game even with Frame Generation off). Since 1.9.17 the shaders' frame clock followed frame generation's own presents instead of the game's frames, so some frames got no shader pass. `loader.log` has a minute line with real frames against shader runs while XeSS presents.
- A game that sits on the loading screen after Press any button now gets a stall report in `loader.log` like other long loads.
- On a 16:10 screen, such as a Steam Deck's, the home screen's latest-video card and the account panel sit where they do at 16:9. The card no longer covers the button bar at the bottom of the screen or runs off its right edge.
- `swofty test session grand_prix` with the F1 2026 box no longer crashes while the session loads. The session now starts under a game setup mode that offers the box's grid, `f1_26` for F1 2026, and `loader.log` names the setup mode it picked.
