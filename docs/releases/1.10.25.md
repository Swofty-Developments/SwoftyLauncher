# 1.10.25

Swofty Launcher for F1 25 1.10.25 fixes F1 25 waiting at a "controller disconnected" message at startup on PCs without an Xbox-style controller.

## Fixes

- Fixed the game waiting behind a "controller disconnected" message at startup on PCs without an Xbox-style controller (keyboard or wheel only), when the launcher starts F1 25 straight into the screen it needs.
- Season HUDs and a season's rules now turn on when a Progressive career is resumed straight into a race weekend.
- Fixed screens such as Choose Driver showing no tiles when an addon replaces the screen with its own copy that leaves out the screen's templates.
- The **Reset interface scale** button now also appears when the launcher is zoomed in too far for its window, and **Ctrl+0** resets the interface scale to Auto from any page.
- Stall reports now include more detail about the loading step the game is stuck on.
- Fixed a crash at startup that could happen with the Steam overlay on.
- Fixed F1 25 sometimes not closing when it exits.

## DB Editor

- With Driver Manager on, **Save** and **Save as Addon** now ask first when the draft changes a head or helmet that Driver Manager's **Game drivers** also sets. Driver Manager's head or helmet replaces the addon's when you play: the popup names each driver and offers **Save anyway**, **Open Driver Manager** and **Cancel**. See [Heads and helmets Driver Manager sets](/using/db-editor#heads-and-helmets-driver-manager-sets).

## Addon API

- A `career::report_season` call made off the flow thread, such as from a `career.loaded` handler, still answers `late`, and the core now runs it at the next flow tick, before the session loads. See [When a season starts](/std/systems/career#when-a-season-starts).
- A `put-resource` of a `.ui` resource without a templates fragment (`syst`) keeps the templates fragment of the copy it replaces, and the build log says so. See [put-resource](/reference/ops/erp#put-resource).
