# 1.9.87

Swofty Launcher for F1 25 1.9.87 learns a profile save that keeps F1 25 on Loading... on an EA app copy under `C:\Program Files`, and a test run without a fixture plays on the session's saves as Play does.

## Fixes

- When the game can't create `swofty\perf.log` in its folder (an EA app copy under `C:\Program Files`), the core writes its performance report to `%LOCALAPPDATA%\Swofty\state\perf-fallback.log`, and the session keeps it as `perf.log`. Until now no report was written there, so the launcher never learned a profile save that kept F1 25 on Loading... after Press any button and never moved it aside, even after a 37-minute stall. `loader.log` names the fallback in a `[perf] the game can't create swofty\perf.log` line. See [A save that stalls at load](/reference/saves#a-save-that-stalls-at-load) and [Performance report](/reference/std/logging#performance-report).
- Send Logs reads that report for the summary's Performance section while the game runs, and sends it as `state/perf-fallback.log`.

## Add-ons

- A `swofty test` run without a fixture, such as `swofty test shell` without `--fixture`, plays on the session's saves as Play does: the profile's launcher saves when the profile has them on. Until now it played on the game's own saves. `career load`, `advance` and `save now` are still refused there. See [Testing your addon](/std/testing).
