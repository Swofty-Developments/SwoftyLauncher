# 1.9.40

Swofty Launcher for F1 25 1.9.40 finishes the HUD load crash fix from 1.9.39, gives added tracks their own weekend format, and fixes two launcher problems on Windows.

## HUD

- Every animation clip the launcher composes for addons' HUD elements is padded to a multiple of 16 bytes. The game's allocator could place some short clips, such as a two-key dial needle sweep, at an address that isn't 16-byte aligned, and loading one could crash the session.

## Tracks

- An added track runs a normal weekend in every season unless its addon asks for sprint weekends. Until now it took its base track's format, so a track added on Zandvoort ran sprint weekends in 2026 careers, and one added on Spa ran them in 2023 to 2025.
- A track addon asks for sprint weekends with `activation.sprint` in its manifest, or `sprint` on a standard library `track` record, listing the data sets (for example `["f1_2026"]`). See [Tracks](/reference/mods/tracks).
- The standard library's `track` schema is now 1.1, which adds the optional `sprint` list.

## EA app

- When an antivirus removes offline play's file from the EA app's folder, the launcher stops with a message naming the antivirus and the folders to exclude, before the game starts. Until now it read the missing file as an EA app repair and waited up to 10 minutes.
- A missing file reported by the EA app's own log counts as an antivirus removal too. A real EA app repair still waits as before.

## Settings

- After you move your addons and saves, Settings shows the folder they moved to. Until now it showed the old path under AppData, which still links to the new folder.
