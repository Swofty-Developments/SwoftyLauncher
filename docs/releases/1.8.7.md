# 1.8.7

Swofty Launcher for F1 25 1.8.7 lets a shader config react to the game. A rule changes the config's options while something is happening: the car on a kerb, its speed, the camera, a replay. The Shaders page's Preview has a triggers strip to try rules on the clip, and it now shows every option and texture format the way the game does.

## Shaders

- A config can hold rules: `[[when]]` blocks that name a signal, a condition and the options to change while it holds, with fade in and fade out times. The editor checks rules as you type and completes signals and their values. See [Rules](/reference/addons/shaders#rules).

  ```toml
  [[when]]
  name = "kerb tracking"
  on = "car.surface"
  is = "kerb"
  wheels = 2
  fade_out_ms = 350
  [when.set.rewind_video]
  noise = 0.12
  ```

- In game, rules read the player's car (speed, revs, gear, throttle, brake, steering, g-force and the surface under each wheel), the camera and replay state, and the session's start, lights out, laps and end. Signals the game doesn't read yet, such as flags and impacts, only work in the Preview, and the editor says so.
- The Preview has a triggers strip under the clip when a config has rules: a control for each signal the rules use and a bar showing each rule's strength as it fades.
- The Preview gives effects options 16 to 19. They were 0 for effects with more than 28 options. The game was not affected.
- The Preview gives declared textures the values their format holds in the game, such as `r16f` with no green or blue, and `rgba8` clamped to 0 to 1.
- The launcher log names the Preview's GPU, the effects and textures it loaded, and its first failure of each kind, so Send Logs carries them.
