# 1.9.92

Swofty Launcher for F1 25 1.9.92 repairs game files that still hold the launcher's changes from an earlier session, which made every Play fail on some EA app copies after the 1.0.145 update. Untested in game.

## Fixes

- Play failed every time before the game started with `applying <addon>: eaid://ui_package/databases/overrides.uidb: ...: an entry with Name=sw_f1_2016 already exists` (also `cs16_mercedes`, `le_mans_2017`) on some EA app copies, until the player repaired F1 25 in the EA app. The game folder still held an archive the launcher had written in an earlier session, and with no original on record for the new game build, the build read it as the game's own file. Play now puts back the archive's original backed up for the earlier game build and builds again, and the log says so (`stale: ... put back its original backed up for game build ...`). When no original is on record, the refusal ends with the EA app's Repair steps and Steam's Verify. **Check conflicts** says the same and that Play puts the original back.
- After a game update, putting the game files back left a file the update did not touch holding the launcher's changes, and forgot that the launcher wrote it. The launcher now puts that file's original back, as it does without an update. A file the update changed stays as the update left it.
- Two addons that add the same entry now stop Play with both their names: `<addon> and <addon> both add the entry Name=<name> (<resource>: <list>); turn one of them off`.
