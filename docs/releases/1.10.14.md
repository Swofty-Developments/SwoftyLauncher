# 1.10.14

Swofty Launcher for F1 25 1.10.14 stops the careers that need add-ons warnings at Play, keeps the careers lost banner to careers that were lost, fixes add-on team colours on the minimap and timing tower, stops a HUD set-up that would close the game, fixes the EA app on Linux, and lets add-ons pick cars, cameras and HUD files more precisely.

## Fixes

- F1 25 could still crash in its own animation code when an animation was sampled at an infinite time. The launcher now gives such an animation its first frame as well.
- On Linux, the launcher saw the EA app as closed while it was open, and started it a second time when launching F1 25 through it.
- On EA app copies, the launcher's settings now reach the game when the EA app starts it.
- Careers that need add-ons no longer show warnings or a popup at Play. Such a career shows as `Missing: <addon>` in the game's Career list, which asks **Load Anyway** or **Back** before it loads. A career of an add-on's career mode is kept in the save while that add-on is off.
- The careers lost banner no longer shows for the game's own records, such as options and trophies, for a career whose add-on was off, or for careers the save still holds after an EA app copy loads it. It names career modes readably.
- Add-on team colours in careers had red and blue swapped on the minimap and the timing tower.
- Play now stops when the HUD add-ons in a profile together make a screen too big for the game's UI, which would close the game as soon as it shows that screen. The message names the add-ons and which ones to turn off. A HUD customisation screen that is too big builds with a warning.
- Add-on HUD records beside Project Halo 0.2.4 no longer stop the build: their animation names now sort after Halo's, and a DRS display no longer fails with "decision drs: 2 stock MVCDs".
- Several add-ons that bring the same HUD screen record, such as season add-ons installed together, now compose it once instead of refusing each other.

## Addon API

- Post-processing effects and shader rules now see the onboard camera in use (`cockpit`, `tcam` or `tcam_offset`) in replays and while driving on the current Steam build, instead of `other`.
- Trackside cameras report `trackside` and the rear-facing pod cameras report `reverse_pod`, in `when.views`, `view.camera` rules, shader constants and the preview.
- `car.profile` can now pick one team, car, package or driver with `cars.team`, `cars.vehicle`, `cars.vehicle_package` and `cars.driver`. A profile whose `cars` named a team was skipped before.
- A season add-on's `car.profile` entries without `within` now apply only in its own seasons and careers, unless they say `"scope": "global"`.
- A HUD file can have a top-level `when`, so an add-on's HUD option can leave the file out.
- `also.<own screen>.hide` keeps elements off a HUD record's own screen.
